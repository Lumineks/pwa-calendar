Дата: 2026-08-27 (ревизия 2 — после трёх префлайт-аудитов)
Статус: ожидает ревью пользователя
База: v1 ship-verdict (audits/audit-3.md), HEAD 4cfac13

Аудиты-источники ограничений (обязательны к прочтению при планировании):
- Археология кода — находки в сессии (связки db↔sync, CI, DayView-инварианты)
- Доменный эксперт: `docs/superpowers/expert/2026-08-27-v2-design.md` (32 MUST)

## Состав релиза

1. **Мульти-аккаунты** — токен → аккаунт, изоляция данных в KV и на клиенте,
   миграция данных подруги с бэкапом и планом отката.
2. **Rich text** — Tiptap (лениво загружаемый, только в DayView), единственная
   фича — цвет текста из фиксированной палитры.
3. **Свайп-навигация** — «палец тянет страницу» в WeekView (недели) и DayView (дни).
4. **Визуальные правки** — кольца спирали → линия, системный шрифт, B2, B7, B10.
5. **Фикс B1** — перечитывание открытого DayView при удалённом обновлении.
6. **PWA-полировка** — сплэш-скрины (B6), онбординг установки (B5).
7. **Тесты** — worker через `@cloudflare/vitest-plugin`, санитайзер через vitest.
8. **CI** — ручной гейт на деплой worker'а + шаг тестов (см. §7; прежняя
   формулировка «CI не меняется» отменена аудитом).

Порядок принципиален: мульти-аккаунты первыми — после них появляется тестовый
аккаунт для безопасной проверки всего остального.

Вне скоупа v2: поиск по записям, Lighthouse, rich-text сверх цвета, тёмная тема, i18n.

## 1. Мульти-аккаунты

### Worker

- Секрет `JOURNAL_TOKENS` — JSON-карта `{"<token>": "<accountId>"}`.
  `accountId`: `[a-z0-9-]{1,32}`. Стартовая карта: токен подруги →
  `marina-actress`, новый токен → `test`.
- Карта парсится **один раз** на изолят (ленивый кэш), не на каждый запрос;
  битый JSON → fail closed: все запросы 401, в лог — причина.
- **Сравнение токенов**: SHA-256-дайджест входящего токена и каждого ключа карты
  (фиксированные 32 байта — `timingSafeEqual` не может бросить исключение на
  разной длине), перебор **всех** пар без раннего выхода, аккумуляция результата.
  Naive-вариант «timingSafeEqual по сырым строкам в цикле» запрещён — бросает
  throw на первой же паре другой длины (текущий guard в v1 существует именно
  поэтому). `verifyToken` возвращает `accountId | null`.
- Секрет `JOURNAL_TOKEN` **остаётся провиженным** до конца окна отката
  (`wrangler rollback` не восстанавливает удалённые секреты — v1-код после
  отката читал бы `undefined`). Удаление секрета — отдельный шаг через
  несколько недель после стабилизации.
- Раскладка KV: `a:<accountId>:entries:<YYYY-MM-DD>`, `a:<accountId>:index`.
  Легаси-ключи после миграции не читаются и не пишутся — архив навсегда.
- `GET /health` → `{ok: true, account: "<accountId>"}` (клиент поле пока не
  использует; тип в `api.ts` обновляется).
- Лимит `body`: **64 КБ в байтах UTF-8** (кириллица = 2 байта/символ), ответ 413.
  Клиент обязан (а) проверять лимит до постановки в очередь и (б) на 413 —
  выводить ошибку и убирать запись из dirty-set, не блокируя остальной синк
  (см. §2 «Ошибки сохранения»).
- Сигнатурные изменения проходят через все хендлеры: `getIndex`/`putIndex`/
  `getEntry`/route-dispatch получают `accountId`.
- Незакоммиченный задел в `worker/src/index.ts` (мертвое поле `JOURNAL_TOKENS`)
  поглощается этой работой.
- `wrangler.toml [env.dev]` сейчас указывает на **продовый** KV-namespace —
  до любых работ создаётся отдельный dev-namespace, и `worker/.dev.vars`
  с dev-картой токенов (иначе `wrangler dev --env dev` не имеет секрета и
  шлёт 401; `.dev.vars` уже в .gitignore).

### Миграция данных подруги (вариант Б: копирование с архивом)

Одноразовый идемпотентный скрипт `worker/scripts/migrate-accounts.mjs`.
Предусловие: **тихое окно ~15 минут** (согласовать с подругой момент, когда она
не пишет) — KV eventually consistent (до 60 с на распространение, включая
негативные ответы), протокол построен с учётом этого.

1. **Бэкап**: полная выгрузка KV в JSON-снапшот с датой. Файл — **вне рабочего
   дерева репозитория** (личный дневник + история с малварью в Aug 2026: файл
   не должен быть достижим для `git add -A` или хука). Продублировать во второе
   надёжное место до шага 2.
2. **Копирование**: `entries:*` → `a:marina-actress:entries:*`; индекс —
   **слияние** (union) в `a:marina-actress:index`, никогда не перезапись.
3. **Верификация**: множество проверяемых ключей строится **независимо** от
   шага 2 — из легаси-`index` и полного `list()` (с пагинацией, 1000/страница);
   инвариант: `|index| == скопировано == сверено`. Побайтовое сравнение с
   retry-with-delay (эвентуальная консистентность даёт ложные расхождения при
   мгновенном чтении). Любое стойкое расхождение — стоп, деплоя нет.
4. Деплой нового worker'а (ручной гейт, см. §7).
5. **Контрольная сверка через прод**: чтение `a:marina-actress:index` и
   выборочных записей **через задеплоенный worker** (не напрямую из KV), повтор
   шага 2/3 в режиме дифф — докопирует записи из окна между копией и деплоем
   (конфликт → больший `updatedAt`).
6. **Откат**: `wrangler rollback` → v1-код читает нетронутые легаси-ключи и
   живой `JOURNAL_TOKEN` (см. выше — секрет не удалён). Записи, сделанные после
   переключения, живут в `a:marina-actress:*`; тот же скрипт переносит их
   обратно в легаси-раскладку.

### Клиент

- **Неймспейс** — синхронный некриптографический хеш токена (FNV-1a 32-bit → hex).
  Обоснование: хеш — не граница безопасности (изоляцию гарантируют карта токенов
  и префиксы KV на сервере); ему нужна только различимость двух известных
  токенов. `crypto.subtle` отвергнут: асинхронность заражает весь старт
  приложения, и он `undefined` при разработке с телефона по
  `http://192.168.x.x` (не secure context) — приложение было бы мертво ровно
  на устройстве из фазы приёмки.
  - Имя Dexie-базы: `journal-<hash>`; localStorage: `journal:<hash>:dirty`,
    `journal:<hash>:backoff`. Токен остаётся в `journal:token`.
- **Новый модуль `src/data/namespace.ts`** владеет текущим неймспейсом и
  разрывает существующий циклический импорт `db.ts ⇄ sync.ts` (в цикл нельзя
  добавлять init-side-effects — оба модуля читают неймспейс из третьего).
- **`db.ts`**: ленивая инициализация. Каждый экспортируемый метод `await`-ит
  общий init-промис; открыть базу до установки неймспейса невозможно (важно:
  `WeekView`/`DayView` дергают db из `$effect`-ов — на порядок эффектов Svelte
  не полагаемся). При смене неймспейса старый Dexie-хендл **закрывается**
  (`db.close()`), чтобы хвост незавершённого pull не писал в чужую базу.
- **`sync.ts`**: `hydrate()` перестаёт быть top-level вызовом на импорте модуля
  (ключи теперь неймспейсные) — переезжает внутрь `syncStart(namespace)`.
  `persistDirty()` — no-op до привязки неймспейса. **При смене неймспейса**
  (hash изменился, не просто logout/login тем же токеном) in-memory состояние
  сбрасывается: `dirty`, `backoffMs`, таймеры — иначе несинхронизированные
  записи одного аккаунта упушатся в другой (кросс-аккаунтная утечка).
- **Logout во время push**: in-flight push прерывается при `clearToken`
  (abort-флаг, проверяемый между итерациями), и 401 перестаёт быть
  poison-pill'ом — запись остаётся в dirty (закрывает Audit-2 S8, который
  с тестовым аккаунтом стал бы ежедневным сценарием).
- **Первичное наполнение нового неймспейса** — полный pull: `GET /entries`
  (только индекс) → выкачка записей **чанками** (range-запросы по ~40 дат;
  worker делает 1 KV-subrequest на дату, лимит Cloudflare free — 50 на
  инвокацию). Пустой индекс при недоступной сети или ошибке — **не** признак
  успешной инициализации: флаг `initialized` ставится только после успешного
  ответа сервера.
- **Дренаж легаси dirty-set**: при первом запуске после обновления, если
  существуют легаси-ключи `journal:dirty` (v1) с записями — они переносятся в
  новый неймспейс до первого push (окно «несинхронизированных офлайн-правок»
  у офлайн-first приложения может быть часами/днями, а новый SW активируется
  на холодном старте спустя дни после деплоя — «исчезающе малое окно» из
  ревизии 1 признано неверным).
- **Офлайн-первый-запуск**: пустая база + нет сети → явное состояние
  «Нужно подключение к интернету для первой загрузки», не пустой журнал.
- Существующая база `journal` на устройствах не мигрируется и не удаляется (архив).

## 2. Rich text (Tiptap)

### Зависимости и загрузка

- Пакеты (по результатам валидации, Tiptap 3.x): `@tiptap/core`, `@tiptap/pm`,
  `@tiptap/extension-document`, `@tiptap/extension-paragraph`,
  `@tiptap/extension-text`, `@tiptap/extension-text-style` (содержит `TextStyle`
  **и** `Color`), `UndoRedo` из `@tiptap/extensions`.
  Все `@tiptap/*` **пинуются на одну точную версию** (peer-зависимости
  exact-pinned; `^`-диапазоны разъезжаются при переустановке).
- Интеграция со Svelte 5 — напрямую через `@tiptap/core` (официального
  Svelte-пакета нет): `$state`-объект, **переприсваиваемый** из `onTransaction`
  (экземпляр Editor не deep-reactive).
- **Ленивый чанк + префетч**: редактор импортируется динамически только в
  DayView. Замеренная цена — ~95 КБ gzip (пол ProseMirror ~86 КБ, урезание
  расширений почти ничего не даёт); лениво — стартовый маршрут и WeekView её
  не платят. WeekView запускает **префетч чанка в простое** (после первого
  рендера, `requestIdleCallback` с таймаут-фолбэком): к моменту тапа по дню
  редактор уже скачан, DayView открывается без задержки. Порог тревоги из
  ревизии 1 заменён этим решением.
- **Спайк-гейт до основной работы**: воспроизвести
  [tiptap#7514](https://github.com/ueberdosis/tiptap/issues/7514) (открытый iOS-баг:
  после выделения текста умирают click-события вне редактора до перезагрузки
  страницы) на целевом iPhone. План на оба исхода: (а) не воспроизводится /
  обходится — палитра и вся хром-навигация вешаются на `touchend`/`pointerup`,
  не на `click`; (б) воспроизводится жёстко — режим «только смена ручки»
  (без окраски выделения) как деградация, решение эскалируется пользователю.

### Редактор

- Замена `<textarea>` в DayView с сохранением всей механики: debounce 300 мс,
  индикатор, флаш при смене даты/unmount. **Авторитетная копия HTML** живёт в
  `$state`-строке, обновляемой на каждый `onUpdate` — cleanup-эффект и
  `onDestroy` (инвариант Audit-1 4e) продолжают работать, даже если экземпляр
  редактора уже уничтожен.
- **Палитра — 6 «ручек»**: чернильный `#2c2412` (дефолт), красный, синий,
  зелёный, фиолетовый, оранжевый (hex подбираются в реализации). Ряд точек в
  шапке DayView, обработчики на `touchend`/`pointerup`. Тап без выделения —
  «текущая ручка»; тап с выделением — окраска фрагмента.
- Программная установка контента — всегда `setContent(html, { emitUpdate: false })`
  (и при первичной загрузке, и из B1-колбэка): иначе echo в dirty-set и
  перезаливка с новым `updatedAt`.
- **Легаси plain text** конвертируется в `<p>` только для отображения; запись
  как HTML происходит **только после реального ввода пользователя** (иначе
  простое пролистывание архива Марины пере-заливает его целиком с новыми
  таймстампами, ломая LWW против её второго устройства).
- **Пустой документ** нормализуется в `''` **в save-пути** (до проверки лимита
  и до `putEntry`), чтобы фокус на пустом дне не порождал запись и строку в
  server-index.
- 16px минимум размера шрифта действует и для contenteditable (iOS zoom floor).

### Ошибки сохранения

413 (превышение лимита) получает отдельную ветку: `saveState = 'error'` с
текстом причины, запись убирается из dirty (не блокирует синк остальных),
локальная копия в Dexie сохраняется. Клиентская предпроверка лимита — до
постановки в очередь.

### Санитизация

- **DOMPurify (~7 КБ gzip)** + hook для палитры — вместо самописного парсера
  (самописные allowlist-парсеры — главный источник mXSS; с мульти-аккаунтами
  HTML-sink впервые становится security-критичным рядом с bearer-токеном в
  localStorage).
- Конфиг: разрешены `p`, `br`, `span`; у `span` атрибуты пересобираются с нуля,
  допустим только `style="color: …"`; цвет валидируется через CSSOM-раунд-трип
  (присвоить `el.style.color`, сравнить нормализованный `rgb(...)` с палитрой),
  не строковым сравнением. Никаких не-XHTML неймспейсов, комментариев,
  `<template>`, `<noscript>`.
- Применяется: превью WeekView, загрузка body в редактор, `transformPastedHTML`.

### Превью WeekView

Рендер санитизированного HTML вместо текстового узла. Сопутствующая CSS-работа
(не «просто подставить `{@html}`»): `white-space: pre-line` больше не нужен
для HTML-веток; `-webkit-line-clamp` **не клампит блочные `<p>`-дети** —
кламп Сб/Вс переделывается (например, `max-height` + `overflow: hidden` по
числу строк); инжектированные `<p>` получают свои правила `margin: 0;
line-height: var(--paper-line-height)`.

### Фикс B1

- Оповещение — из обёртки над `dbWriteFromServer`, чтобы срабатывали **оба**
  пути: `pull()` и 409-ветка внутри `push()` (409 — ровно случай «редактор
  показывает значение, которое сервер только что отверг»).
- Guard: пропускать обновление, пока `editor.view.composing === true`
  (iOS-предиктивный ввод для русского — это постоянная композиция; guard по
  фокусу недостаточен и ломает model-DOM-sync). Если контент заменён колбэком —
  `pendingSave` сбрасывается и debounce отменяется (иначе уход со страницы
  пере-зальёт серверное значение под новым таймстампом).

## 3. Свайп-навигация

Компонент `src/components/SwipePager.svelte` (лента prev/current/next,
transform за пальцем, доводка по порогу ~35% ширины или скорости флика,
колбэк `onNavigate(dir)` — навигацию выполняет **вьюха**, у которой уже есть
`base`; `BASE_URL`-префикс выносится в общий модуль, четвёртой копии не будет).

- Горизонтальность жеста: угол < ~30°, иначе жест отдаётся вертикальному скроллу.
- **Конфликт с системным edge-swipe**: фиксированная «мертвая зона 24px» —
  миф (ширина зоны WebKit не документирована). Механизм подавления —
  `preventDefault()` на `touchstart` c `{passive: false}` (Safari по умолчанию
  passive) для жестов, начатых у краёв; учитывать, что в iOS 26 контендится и
  правый край (swipe-forward). Двойная навигация (система + приложение)
  проверяется на устройстве в фазе приёмки.
- `navigate()` для свайпов — **push** (история недель = осмысленный back);
  зафиксировано как семантика, а не случайность.
- **WeekView**: панели — соседние недели; Dexie-выборка ±1 неделя. Pull-окно
  синка (`currentPullRange`) **следует за просматриваемой неделей**, а не за
  «сегодня» (иначе за пределами ±3 недель от текущей даты соседние панели
  въезжают пустыми навсегда).
- **DayView**: перед навигацией — существующий флаш; последовательность при
  жесте: blur редактора → дождаться стабилизации visual viewport (документиро-
  ванный iOS-баг: `visualViewport.offsetTop` не сбрасывается сразу после
  скрытия клавиатуры, фиксированная шапка уезжает) → затем transform.
- **Layout-перестройка DayView**: `position: fixed; inset: 0` несовместим с
  transform-предком (transform меняет containing block; `backdrop-filter`
  шапки — тоже). DayView переходит на нефиксированное позиционирование внутри
  панели пейджера; `env(safe-area-inset-top)` перепроверяется в новом контексте.
  Существующий `transition:fly` удаляется — навигацию анимирует пейджер.

## 4. Визуальные правки

- **SpiralBinding**: удалить `.ring`-овалы и проп `count` (правится и вызов в
  WeekView); линия `.rod` остаётся, непрозрачность ~0.35 → ~0.5 (подобрать).
- **Шрифт**: редактор и превью — системный стек
  `-apple-system, system-ui, 'Segoe UI', Roboto, sans-serif` (на iPhone — SF Pro,
  как в Telegram iOS). Пересчитать посадку базовой линии на линовку в **двух**
  независимо откалиброванных местах: DayView (`padding-top`; комментарий v1
  устарел — реальный `--paper-line-height` = 18px, не 20px) и превью WeekView
  (12px Georgia — второй сайт калибровки). `font-size: 16px` в редакторе —
  неприкосновенен (iOS zoom floor).
- **B2**: единый общий store `today` (один `setTimeout` до локальной полуночи +
  `visibilitychange`), потребляется WeekView и MonthPicker — две независимые
  «часовые» точки v1 (включая нереактивный `$derived` в MonthPicker) убираются.
- **B7**: `.preview` → `overflow-y: auto` + скрытие скроллбара.
- **B10**: удалить `src/lib/Counter.svelte`, `src/assets/{hero.png,svelte.svg,vite.svg}`
  (проверено: ссылок нет).

## 5. PWA-полировка

- **Сплэш-скрины (B6)**: `pwa-asset-generator` 8.x (жив, поддерживается;
  требует локально установленный Chrome — запускается на машине разработчика,
  не в CI; результат коммитится). Обязателен `--path /pwa-calendar` —
  дефолтные root-relative href'ы 404-ят под сабпутём GitHub Pages (грабли
  коммита `0a3dc1c`; заодно чинится уже сломанный относительный href иконки в
  `404.html`-фолбэке — все href в `index.html` переводятся на
  `/pwa-calendar/`-абсолютные). Тёмные варианты media-query указывают на те же
  светлые изображения (устройство без совпавшего query показывает белый экран).
  Изображения — в `public/`, в precache-глоб `vite.config.ts`.
- **Онбординг (B5)**: порядок **установка → токен**, не наоборот: Safari и
  standalone-PWA имеют **раздельные** хранилища (WebKit 181849) — токен,
  введённый в Safari до установки, в установленном приложении отсутствует.
  `InstallHint.svelte` при iOS Safari + не-standalone показывается **вместо**
  формы токена (с опцией «продолжить в браузере» для нестандартных случаев):
  три шага «Поделиться → На экран „Домой“ → Добавить», закрытие запоминается в
  localStorage (без неймспейса — свойство устройства).

## 6. Тесты

- **Worker — `@cloudflare/vitest-plugin`** (переименованный
  `@cloudflare/vitest-pool-workers`, совместим с wrangler ^4.90 из
  worker/package.json; конфиг читает существующий wrangler.toml). Ручной мок
  KV отвергнут: `crypto.subtle.timingSafeEqual` не существует в Node — самая
  security-критичная функция была бы нетестируемой. Покрытие: verifyToken
  (валидные токены обоих аккаунтов, невалидный, пустой, другая длина, битая
  карта → fail closed), изоляция префиксов между аккаунтами, LWW/409,
  целостность index, лимит 64 КБ (UTF-8), валидация дат. Это же покрывает
  «прогон на miniflare» из ревизии 1.
- **Санитайзер (vitest, jsdom)**: пропуск разрешённого, вырезание тегов/
  атрибутов/скриптов/неймспейсов, цвет вне палитры, plain-text-конвертация,
  нормализация пустого, mXSS-регрессии из DOMPurify-тест-корпуса (выборочно).
- **Скрипт миграции**: верификационный режим = его тест; репетиция на
  dev-KV-namespace (создаётся в §1) до прода.
- E2E остаётся ручным по традиции аудитов v1.

## 7. CI и порядок выката

### CI (правится ДО начала фазы A)

- `deploy.yml`: job `deploy-worker` снимается с автотриггера по пушу в `main` —
  переводится на `workflow_dispatch` (ручной запуск). Автодеплой worker'а
  ломал бы протокол миграции: новый код читает префиксы, которых ещё нет →
  журнал Марины «пуст». Деплой фронта остаётся автоматическим.
- Добавляется job тестов (root + worker), block-ующий деплой-jobs (`needs:`).
- Лок-файлы (`package-lock.json`, `worker/package-lock.json`) — разделяемый
  ресурс: `npm ci` падает при рассинхроне; каждое изменение зависимостей
  регенерирует лок в том же коммите.

### Фазы

1. **Фаза A — аккаунты**: CI-гейт → dev-namespace + `.dev.vars` → worker
   (мульти-токены, префиксы, лимит) + тесты → миграция по протоколу §1
   (с тихим окном) → клиентские неймспейсы + чанкованный полный pull + дренаж
   легаси-dirty → тестовый аккаунт → смоук: Марина ничего не заметила,
   тестовый аккаунт пуст и независим.
2. **Фаза B — фичи** (на тестовом аккаунте): спайк tiptap#7514 → rich text +
   B1 → свайпы → визуальные правки → PWA-полировка.
3. **Фаза C — приёмка**: смоук на реальном iPhone на тестовом аккаунте, включая
   чеклист A–L из audit-3 Step 2 (не закрыт с v1), двойную навигацию жестов и
   сплэш-скрины на устройстве; проверка легаси-записей Марины (открываются,
   красятся, синкаются).
