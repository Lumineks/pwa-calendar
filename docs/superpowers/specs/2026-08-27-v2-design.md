# v2 — Дизайн-спецификация

Дата: 2026-08-27
Статус: утверждена пользователем (устно в сессии), ожидает ревью письменного текста
База: v1 ship-verdict (audits/audit-3.md), HEAD 6571752

## Состав релиза

1. **Мульти-аккаунты** — токен → аккаунт, изоляция данных в KV и на клиенте, миграция данных подруги с бэкапом и планом отката.
2. **Rich text** — Tiptap в минимальной сборке, единственная фича — цвет текста из фиксированной палитры.
3. **Свайп-навигация** — «палец тянет страницу» в WeekView (недели) и DayView (соседние дни).
4. **Визуальные правки** — удалить кольца спирали (оставить линию), системный шрифт вместо Georgia, B2 (полночь), B7 (скроллбар превью), B10 (чистка скаффолда).
5. **Фикс B1** — перечитывание открытого DayView при удалённом pull.
6. **PWA-полировка** — сплэш-скрины (B6), онбординг установки (B5).
7. **Тесты** — vitest для worker'а и санитайзера HTML.

Порядок принципиален: мульти-аккаунты идут первыми — после них появляется тестовый
аккаунт, на котором безопасно проверяется всё остальное, не касаясь данных подруги.

Вне скоупа v2: поиск по записям, Lighthouse-замер, любые rich-text-фичи кроме цвета
(жирный, списки, заголовки — вставка очищается), тёмная тема, i18n.

## 1. Мульти-аккаунты

### Worker

- Секрет `JOURNAL_TOKENS` — JSON-карта `{"<token>": "<accountId>"}`.
  `accountId`: `[a-z0-9-]{1,32}`. Стартовая карта: токен подруги → `marina-actress`,
  новый токен → `test`.
- `verifyToken` перебирает **все** пары карты с constant-time сравнением каждой
  (`crypto.subtle.timingSafeEqual`, без раннего выхода) и возвращает `accountId | null`.
- Старый секрет `JOURNAL_TOKEN` удаляется из worker'а и из wrangler-секретов.
  Токен подруги не меняется — на её устройстве ничего перевводить не нужно.
- Раскладка KV: `a:<accountId>:entries:<YYYY-MM-DD>`, `a:<accountId>:index`.
  Легаси-ключи (`entries:*`, `index`) после миграции не читаются и не пишутся —
  остаются архивом навсегда.
- `GET /health` → `{ok: true, account: "<accountId>"}`.
- Новое ограничение: `body` ≤ 64 КБ (400 при превышении).
- Незакоммиченный задел в `worker/src/index.ts` (поле `JOURNAL_TOKENS`, неиспользуемая
  переменная) поглощается этой работой.

### Миграция данных подруги (вариант Б: копирование с архивом)

Одноразовый идемпотентный скрипт `worker/scripts/migrate-accounts.mjs` (запуск вручную,
через wrangler API):

1. **Бэкап**: выгрузить все ключи KV в локальный JSON-снапшот с датой в имени.
   В git не коммитить (личные данные). Рекомендация: продублировать файл во второе
   надёжное место до шага 2.
2. **Копирование**: `entries:*` → `a:marina-actress:entries:*`, `index` →
   `a:marina-actress:index`. Легаси-ключи не удаляются.
3. **Верификация**: повторно прочитать оригинал и копию, побайтово сравнить каждое
   значение; отчёт «N ключей, N совпадений». Любое расхождение — стоп, деплоя нет.
4. Деплой нового worker'а.
5. **Контрольный диф**: повторный запуск скрипта в режиме сравнения — записи,
   сделанные подругой в окно между шагами 2 и 4, докопируются (при конфликте
   побеждает больший `updatedAt`).
6. **Откат**: `wrangler rollback` на предыдущую версию — она читает нетронутые
   легаси-ключи, откат мгновенный. Записи, сделанные после переключения, живут в
   `a:marina-actress:*`; тот же скрипт умеет перенос в обратную сторону.

### Клиент

- Всё локальное состояние становится пер-токенным. Ключ неймспейса — короткий хеш
  токена: `sha256(token)` → первые 12 hex-символов.
  - Имя Dexie-базы: `journal-<hash>`.
  - localStorage: `journal:<hash>:dirty`, `journal:<hash>:backoff`.
  - Сам токен остаётся в `journal:token` (одна активная сессия на устройство).
- Гарантия изоляции: другой токен → другая локальная база → другой префикс в KV.
  Вход тестовым токеном на любом устройстве не может ни увидеть, ни запушить данные
  `marina-actress`.
- `db.ts` перестаёт быть модульным синглтоном: база открывается лениво после того,
  как известен токен (фабрика/инициализация из App.svelte вместе с syncStart).
- Существующая база `journal` на устройствах не мигрируется и не удаляется (архив).
  Новая пустая база наполняется **одноразовым полным pull'ом**: `GET /entries` (индекс)
  → выкачка всех дат одной range-выборкой от первой до последней даты индекса.
  Триггер: первый syncStart для неймспейса, у которого локальная база пуста.
  Требует онлайна; офлайн-первый-запуск даёт пустую базу, которая наполнится при
  появлении сети — потерь нет, источник истины KV (модель v1).
- Известное принятое окно: несинхронизированные правки в легаси dirty-set на момент
  обновления приложения осиротеют (легаси-база — архив). Окно исчезающе мало:
  правки уходят в KV через ~3 с после ввода.

## 2. Rich text (Tiptap)

- Зависимости: `@tiptap/core`, расширения `Document`, `Paragraph`, `Text`,
  `TextStyle`, `Color`, `History`. Ничего больше. Ожидаемая цена ~40–60 КБ gzip.
- `<textarea>` в DayView заменяется на Tiptap-редактор. Сохраняется вся текущая
  механика: debounce 300 мс, индикатор «Сохраняется…/Сохранено», флаш незаписанного
  при смене даты и при unmount (логика cleanup-эффекта переносится как есть).
- **Палитра — 6 «ручек»** (единственный источник — константа в одном модуле):
  чернильный `#2c2412` (по умолчанию), красный, синий, зелёный, фиолетовый,
  оранжевый (точные значения подбираются в реализации под бумажную гамму).
  UI: ряд цветных точек в шапке DayView. Тап без выделения — переключает «текущую
  ручку» для дальнейшего ввода; тап с выделением — красит выделенный фрагмент.
- **Формат хранения**: `body` остаётся строкой и содержит HTML от Tiptap
  (`<p>`, `<span style="color: …">`). Синк, worker, LWW — без изменений.
- **Легаси plain text**: при загрузке в редактор конвертируется построчно в `<p>`
  (детект: строка не начинается с `<p>`). Сохраняется уже как HTML — односторонний
  апгрейд, обратная конвертация не нужна.
- **Пустой документ** нормализуется в `''` (Tiptap-пустышка `<p></p>` не должна
  порождать записи и не должна ломать существующую семантику «пустая строка»).
- **Санитизация**: модуль `src/data/sanitize.ts` с allowlist-парсером (DOMParser):
  разрешены `p`, `br`, `span` только со `style="color: <цвет из палитры>"`;
  всё остальное — в текст. Применяется при рендере превью WeekView и при загрузке
  body в редактор. Вставка извне проходит через тот же фильтр.
- **Ритм строк**: абзацы редактора получают `line-height: var(--paper-line-height)`,
  нулевые margin — текст сидит на линовке; базовая линия перекалибруется под
  системный шрифт (см. §4), методика расчёта — как в комментарии DayView v1.
- **Превью WeekView** рендерит санитизированный HTML (цвета видны в превью).

### Фикс B1 (в этой же работе)

`sync.pull()` при записи в Dexie оповещает подписчиков (лёгкий callback-реестр в
sync.ts: `onEntryUpdated(date, cb)`). Открытый DayView на эту дату: если редактор
не в фокусе — перечитывает содержимое; если в фокусе (пользователь печатает) —
пропускает, следующий push разрешит по LWW.

## 3. Свайп-навигация

Один переиспользуемый компонент `src/components/SwipePager.svelte`:
горизонтальная лента из трёх панелей (prev / current / next, слоты),
`transform: translateX` следует за пальцем, на отпускании — доводка по порогу
расстояния (~35% ширины) или скорости флика, затем колбэк `onNavigate(dir)` →
`navigate()` и сброс transform.

- Жест засчитывается только при доминирующей горизонтали (угол < ~30°), иначе
  отдаётся вертикальному скроллу превью.
- Стартовая зона отступает ~24px от краёв экрана — не конфликтует с системным
  edge-swipe iOS (который остаётся рабочим и полезным: история = предыдущие недели).
- **WeekView**: панели = соседние недели; выборка записей расширяется до ±1 недели,
  чтобы соседние страницы въезжали заполненными.
- **DayView**: панели = соседние дни; перед навигацией срабатывает существующий
  флаш отложенного сохранения; на старте жеста редактор блюрится (клавиатура
  прячется, не прыгает во время анимации).

## 4. Визуальные правки

- **SpiralBinding**: удалить `.ring`-овалы и проп `count`; оставить линию `.rod`,
  увеличив непрозрачность градиента (примерно 0.35 → 0.5, подобрать визуально).
- **Шрифт**: редактор и превью переходят с Georgia на системный стек
  `-apple-system, system-ui, 'Segoe UI', Roboto, sans-serif` (на iPhone — SF Pro,
  тот же шрифт, что в Telegram iOS). Пересчитать `padding-top` посадки текста на
  линовку под метрики нового шрифта (формула задокументирована в DayView).
- **B2**: `today` в WeekView/MonthPicker — `$state`, обновляемый `setTimeout` до
  ближайшей локальной полуночи + на `visibilitychange`.
- **B7**: `.preview` → `overflow-y: auto` + скрытие скроллбара
  (`scrollbar-width: none`, `::-webkit-scrollbar { display: none }`).
- **B10**: удалить `src/lib/Counter.svelte`, `src/assets/hero.png`,
  `src/assets/svelte.svg`, `src/assets/vite.svg`.

- **Сплэш-скрины (B6)**: `pwa-asset-generator` от `public/icon-512.png` на фоне

- **Онбординг (B5)**: `src/components/InstallHint.svelte` поверх TokenGate при

  устройства, не аккаунта).

## 6. Тесты

- **Worker (vitest, мок KVNamespace, чистые юнит-тесты хендлеров)**:
  - `verifyToken`: валидный токен каждого аккаунта, невалидный, пустой,
    другая длина, пустая/битая карта токенов;
  - изоляция префиксов: запись в `test` не видна из `marina-actress` и наоборот;
  - LWW/409, целостность `index` (PUT/DELETE), лимит 64 КБ, валидация дат.
- **Санитайзер (vitest)**: пропуск разрешённого, вырезание тегов/атрибутов/скриптов,
  цвета вне палитры, plain-text-конвертация, нормализация пустого документа.
- **Скрипт миграции**: верификационный режим и есть его тест; плюс прогон на
  локальном miniflare-KV перед продом.
- E2E остаётся ручным по традиции аудитов v1.

## 7. Порядок выката

1. **Фаза A — аккаунты**: worker (мульти-токены, префиксы, лимит) + тесты →
   миграция по протоколу §1 → клиентские неймспейсы + полный pull → создание
   тестового аккаунта → смоук: подруга ничего не заметила, тестовый аккаунт пуст
   и независим.
2. **Фаза B — всё остальное** разрабатывается и проверяется на тестовом аккаунте:
   rich text + B1, свайпы, визуальные правки, PWA-полировка.
3. **Фаза C — приёмка**: смоук на реальном iPhone на тестовом аккаунте, включая
   не закрытый с v1 чеклист A–L (audit-3, Step 2); ручная проверка легаси-записей
   подруги (открываются, красятся, синкаются).

CI не меняется (GitHub Pages + wrangler deploy по пушу в `main`).

## Открытые допущения

- Точные hex-значения пяти цветных «ручек» подбираются в реализации (утверждена
  только структура: 6 цветов включая чернильный по умолчанию).
- Реальный размер Tiptap-бандла проверяется в первой же сборке; порог тревоги —
  если общий gzip-бандл превысит ~150 КБ, обсуждаем урезание (History — первый
  кандидат на выброс).
